## Who I am in threads

<!-- Paste your section here. -->
I am a recent college grad with a major in CS and minor in Data Science.
I contribute fixes to issues I think affects me, and I use GitHub whenever I use software.

## Rules I write by

<!-- Paste your rules here, wrong/right pairs and all. Add any rule
the PR register needs that your comments did not. -->
- Wrong: Multiple paragraphs larger than the issue requires.
- Right: Few short sentences describing the problem & fixes. Additional comments are made separately.
- Wrong: A block of text has emojis
- Right: No emojis at all. In somewhat "casual" contexts, an ascii smiley is fine.
- Wrong: Comments that describe code.
- Right: Comments that explains why the code is necessary. I don't like comments in code as code should explain itself. It's still useful for say, doing complicated-levels of math or anything that would require specialized education to know immmediately.

## Things I never post

<!-- Paste your list here; extend it if PR descriptions tempt you
toward new ones (claiming coverage the evidence does not show is the
classic). -->
1. Emojis
2. Timelines, unless if I'm in a private work repo, things will get done whenever.
3. "Friendly" tones. It's just code; not intentionally mean, but fluff isn't necessary.
4. General comments. This isn't Twitter.
